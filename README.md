# apartaments

Обычная версия сайта Bergedorf Apartments на HTML, CSS, JavaScript и PHP. Сайт только на немецком, без переключателя языков и русских страниц. Реальные фото первой демонстрационной карточки; ещё 14 карточек — согласованные заглушки. Заявки подключены к адресу `Vp@simplyfood.de` через серверную почту без SMTP-пароля. В Local письма остаются в Mailpit; внешняя доставка проверяется на реальном хостинге.

Этот репозиторий содержит самостоятельную версию сайта. Для размещения требуется PHP-хостинг с корнем сайта `public/`.

## Посмотреть сайт

Требуются Node.js 22+ и PHP 8.2+. Зависимостей npm нет.

```powershell
npm run build
npm run dev
```

Сайт: http://127.0.0.1:4173/ . На Windows можно запустить `start-site.cmd`. Сервер останавливается сочетанием Ctrl+C. Файлы HTML открывайте через сервер: абсолютные пути ресурсов и ES-модули рассчитаны на HTTP.

## Что реализовано

- Светлая молочно-оливковая палитра, Cormorant Garamond + Manrope, локальные WOFF2 с лицензиями.
- Первый экран, 15 апартаментов, общая комплектация, Self Check-in, адрес, внешняя карта, FAQ, контакты.
- Выбор апартамента, раскрытие всех карточек, переключение 7 фото прямо в карточке по миниатюрам. Увеличение показывает текущий кадр; полноэкранная галерея поддерживает стрелки/клавиатуру/свайп.
- Фиксированная шапка; выразительная кнопка Menü; мобильное меню с компенсацией scrollbar, скрытием scrollbar, сохранением позиции, Escape, фокусом, мягким появлением панели и последовательным входом пунктов.
- Форма: поля с подписями, проверки имени/email/телефона/дат, отдельное согласие, явный режим предварительного показа. Выбранный номер переносится в запрос.
- Cookie-плашка, выбор необходимых функций, настройки и повторное открытие; без аналитики и рекламы. FAQ плавно раскрывается и сворачивается с изменением высоты.
- 5 немецких страниц: главная, Impressum, Datenschutz, Einwilligung и Cookie-Hinweise.
- WebP 480/960/1536 px, responsive srcset, отложенная загрузка изображений, приоритет первого экрана, локальные шрифты, reduced motion, семантический HTML и SVG-иконки.
- Предпросмотр закрыт от поисковых роботов; при финальной сборке с доменом включаются canonical/Open Graph/sitemap. JSON-LD содержит только подтверждённые общие сведения.

## Где редактировать

| Сведения | Файл |
|---|---|
| Номер, название, описание, реальные параметры, фото каждой квартиры | `src/apartments.mjs` |
| Немецкие тексты, телефон и адрес | `src/content.mjs` |
| Общая структура секций и компонентов | `src/templates.mjs` |
| Юридические страницы | `src/legal.mjs` |
| Цвета, шрифты, размеры и основные токены | `public/assets/css/theme.css` |
| Компоненты и адаптив | `public/assets/css/site.css` |
| Кнопка Menü, анимации меню/FAQ, выбор фото | `public/assets/css/interactions.css` |
| Меню, каталог, галерея, cookies и форма | `public/assets/js/app.mjs` |
| Настройки отправки, не публикуемые в document root | `server/config.local.php` |

После редактирования содержимого выполнить `npm run build`. Номер 01 для имеющейся фотосерии — демонстрационное назначение, реальный номер заказчик ещё не подтвердил. Площади, вместимость и цены не выдуманы. Для других квартир можно заполнить массив `photos` локальными именами и снять флаг `preview`; перед публикацией проверить фактические данные и картинки.

## Настоящая отправка формы

1. Разместить сайт на HTTPS-хостинге с PHP, указав **только `public/`** как корень сайта. `server/` должен оставаться вне публичного корня.
2. Скопировать `server/config.example.php` в `server/config.local.php`.
3. Указать реальные `recipient` и `sender`, финальный `public_origin` без завершающего слеша и случайный `rate_secret` длиной не менее 32 символов. Убедиться, что хостинг настроил `mail()` и отправитель разрешён почтовым сервером. Email-заглушки и домены `.example` не проходят конфигурацию.
4. Дополнить юридические документы фактическими сведениями о хостинге, почтовом поставщике, месте хранения, сроках удаления и условиях передачи; утвердить их у оператора. Для отправки установить `enabled` в `true`; отдельного технического флага `legal_approved` больше нет.
5. Назначить запуск `php server/cleanup-rates.php` каждые 10 минут. Файлы временных ограничений не содержат текста заявок; сохранён только HMAC-хеш IP и счётчик.
6. Проверить контролируемую заявку и её получение на указанном ящике. Локальные тесты 4 октября 2026 подтверждены в Mailpit; внешние письма не отправлялись.

Защита обработчика: строгий origin, CSRF, HttpOnly/Secure/SameSite-сессия, JSON и ограничение тела 16 КБ, серверная проверка полей и согласия, honeypot, пять попыток за десять минут, проверка заголовков email. Успех означает принятие сообщения серверной почтовой функцией, а не гарантию доставки или подтверждение резервации. На production-хостинге проверьте реальное получение и обработку заявок.

## Публикация и SEO

В PowerShell перед окончательной сборкой:

```powershell
$env:SITE_ORIGIN = 'https://ВАШ-ФИНАЛЬНЫЙ-ДОМЕН'
npm run build
```

Заменить домен на реальный. Без `SITE_ORIGIN` сборка сохраняет `noindex, nofollow`, `Disallow: /` и пустой sitemap — так прототип не индексируется с незаполненными данными. Не включайте индексирование до заполнения контента и реквизитов.

В `public/.htaccess` предусмотрены запрет листинга каталогов, MIME для ES-модулей/WebP/WOFF2, защитные заголовки, сжатие текста и кеширование ресурсов. Для Nginx настроить эквивалент самостоятельно; PHP встроенный сервер используется только локально. Включить HTTPS, ограничить публичный корень `public/`, проверить конфигурацию и доставку mail, сделать резервную копию перед обновлениями. При изменениях CSS/JS сбрасывать серверный кеш либо версионировать пути ресурсов.

## Проверки

```powershell
npm run verify
```

Команда пересобирает страницы, запускает Node-тесты, PHP-проверки валидации/конфигурации и синтаксиса. Browser QA хранится в `tests/browser-regressions.js`; запуск — через Playwright MCP `browser_run_code_unsafe` с `filename`. Проверены ширины 1440, 768, 360 и 320 px. Итоги и снимки — в `docs/verification.md` и `artifacts/`.
